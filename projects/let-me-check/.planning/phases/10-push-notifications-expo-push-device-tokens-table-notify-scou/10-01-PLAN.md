<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> device_push_tokens | Authenticated client writes its own push token rows |
| checks.status write -> send-push | pg trigger crosses into the Edge Function with a service-role bearer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | device_push_tokens insert (register another user's token) | mitigate | RLS `WITH CHECK (auth.uid() = user_id)` on INSERT; client can only write rows under its own user_id |
| T-10-02 | Information Disclosure | reading another user's tokens | mitigate | RLS `USING (auth.uid() = user_id)` on SELECT; cross-user read returns zero rows (PUSH-03 pgTAP) |
| T-10-03 | Elevation of Privilege | trigger leaking the service-role key | mitigate | Key read from a database GUC set out-of-band (Vault), never hardcoded in migration SQL; alternative Dashboard-webhook injects header server-side |
| T-10-04 | Denial of Service | a push dispatch failure blocking the `dispatching` transition | mitigate | http_post wrapped in EXCEPTION WHEN OTHERS THEN NULL + null-GUC guard — the trigger always RETURN NEW; the transition never blocks (D-03) |
</threat_model>
