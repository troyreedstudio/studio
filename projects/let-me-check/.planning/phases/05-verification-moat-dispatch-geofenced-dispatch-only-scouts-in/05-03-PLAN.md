<objective>
Build the hard GPS auto-reject gate (D-04/D-05, VER-01): a `verify-clip` Edge Function that compares the clip's filmed GPS against the venue/check coord using the tunable `film_fence_max_m` (30 m hard cap), and wire it into `mux-webhook` so it runs BEFORE the `delivered` transition. A clip within the fence proceeds to delivered (and capture, unchanged). A clip beyond 30 m is auto-rejected: the check is re-dispatched via `reset_check_for_redispatch`, the webhook returns without delivering, and `stripe-capture` never fires (Seeker not charged, Scout not paid). Deno tests pin both paths first.

Purpose: this is the trust half of the moat and the one hard gate in the system. It must run before `delivered` because once delivered the Seeker has the clip and is charged.
Output: verify-clip Edge Function + tests + the mux-webhook gate + extended webhook tests.
</objective>

```ts
export async function handleVerifyClip(
  checkId: string,
  deps: { svc: Svc },
): Promise<{ passed: boolean; distance_m: number | null }>
```
Logic:
1. Read the LATEST clip for the check (Pitfall 5): `from('clips').select('filmed_lat, filmed_lng, filmed_accuracy_m').eq('check_id', checkId).order('created_at', { ascending: false }).limit(1).single()`.
2. Read `from('checks').select('coord').eq('id', checkId).single()`.
3. If `clip.filmed_lat` is null/undefined OR `clip.filmed_lng` is null OR `check.coord` is null: log `check.gps_unverifiable` via `rpc('log_event', { p_event_type, p_subject_type:'check', p_subject_id: checkId, p_context: { reason:'no_gps_data' } })`, do NOT set gps_verified=true, return `{ passed: true, distance_m: null }` (can't reject what we can't verify — honest-Scout-friendly; signage advisory still records separately in Plan 04).
4. Read `film_fence_max_m` from `market_config` (`.select('film_fence_max_m').limit(1).single()`), default 30.
5. Compute distance server-side: `rpc('distance_m', { p_lat: clip.filmed_lat, p_lng: clip.filmed_lng, p_geog: check.coord })`. (distance_m handles lng/lat order internally — Plan 01.)
6. `const passed = dist <= maxFence;`
7. `from('clips').update({ gps_verified: passed }).eq('check_id', checkId)`.
8. `rpc('log_event', { p_event_type: passed ? 'check.gps_verified' : 'check.gps_rejected', p_subject_type:'check', p_subject_id: checkId, p_context: { distance_m: dist, film_fence_max_m: maxFence, filmed_accuracy_m: clip.filmed_accuracy_m } })`.
9. Return `{ passed, distance_m: dist }`.

NOTE: verify-clip does NOT itself call reset_check_for_redispatch or transition delivered — the mux-webhook orchestrates that (Task 3) so the gate sits exactly before delivered. (The test references reset_check_for_redispatch on the mock to confirm verify-clip never calls it on the pass path.)
