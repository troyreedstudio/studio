<objective>
Wire the client so the Plan 02 dispatch RPC and Plan 03 GPS gate actually receive data: (1) a `scout-location.ts` helper that upserts the online Scout's location to `scout_locations`; (2) a `dispatch.ts` wrapper for `list_open_checks_for_scout`; (3) dashboard uses expo-location foreground watch to keep location fresh and shows the geo-filtered list; (4) `createCheck` populates `checks.coord`; (5) the recorded clip's GPS (lat/lng + accuracy) flows through `mux-upload-url` into `clips.filmed_lat/filmed_lng/filmed_accuracy_m` so verify-clip has real data.

Purpose: dispatch and verification are server-side, but they are inert without the client sending location and the clip's GPS. This plan closes those two seams (the Phase-3 `_gps` parameter that was ignored finally gets persisted).
Output: two new lib files + tests, dashboard + filming edits, createCheck coord population, mux-upload-url persisting filmed GPS.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scout device → scout_locations | Scout writes own location row; RLS confines to own row |
| Scout device → mux-upload-url (filmed GPS) | Untrusted GPS persisted; the hard check is verify-clip server-side (Plan 03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-22 | Tampering | Scout reports false location to see far jobs | mitigate | Seeing a job is harmless without accepting; accept_check re-checks geo server-side (Plan 02); film GPS re-checked in verify-clip (Plan 03) |
| T-05-23 | Information Disclosure | dashboard leaks others' locations | mitigate | Client only ever reads its own scout_locations row (RLS); cross-row dispatch is the SECURITY DEFINER RPC, returns checks not locations |
| T-05-24 | Input Validation | non-finite filmed GPS in upload body | mitigate | mux-upload-url validates finite numbers before persisting; verify-clip treats null/NaN as unverifiable |
| T-05-25 | Privacy | continuous foreground location tracking | accept | Foreground-only watch while explicitly online; setScoutOffline + subscription.remove() on toggle/unmount; documented consent via go-online |
</threat_model>
