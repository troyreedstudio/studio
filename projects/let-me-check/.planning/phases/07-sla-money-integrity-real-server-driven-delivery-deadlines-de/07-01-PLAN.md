<objective>
Make delivery deadlines REAL at the database layer. Today the filming countdown is a cosmetic client constant (420/600s) that resets on app reopen and has zero server effect. This plan adds the authoritative `deadline_at` column, seeds it atomically inside `accept_check()` from the check's tier (no client influence), and writes the `expire_stale_filming()` sweeper that auto-expires accepted-but-undelivered checks past their deadline. It also tightens the unclaimed dispatch window to 5 minutes per D-02.

This is the foundation wave: the migration must land before the Edge Functions (Plan 02) and client wiring (Plan 03) that read `deadline_at`. It is additive-only and safe to push behind the existing schema (mirrors the Phase 5/6 migration shape).

Purpose: Server owns the SLA clock (D-01), enforces it on a sweep (D-03), and frees stuck checks (D-02).
Output: Migration 0015 + two RED pgTAP scaffolds the deploy wave (Plan 04) will run live.
</objective>

```sql
create or replace function public.expire_stale_dispatching()
returns int language plpgsql security definer set search_path = public
as $$
declare v_count int := 0; r record;
begin
  for r in select id from public.checks
    where status = 'dispatching' and scout_id is null
      and updated_at < now() - make_interval(secs => v_timeout_s)
  loop
    perform public.transition_check(r.id, 'no_scout',
      jsonb_build_object('reason', 'dispatch_timeout'));
    v_count := v_count + 1;
  end loop;
  return v_count;
end; $$;
```
