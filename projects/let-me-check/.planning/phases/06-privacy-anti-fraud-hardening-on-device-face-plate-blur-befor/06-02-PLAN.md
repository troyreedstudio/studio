<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mux thumbnail → Vision | Mux signed playback requires a JWT; Vision must receive base64 bytes, never a 401-prone signed URL |
| Vision API key → client | GOOGLE_VISION_API_KEY must stay in Deno.env, never in the RN bundle |
| client fraud_signals → verdict | client supplies the raw signal bag; the verdict (score/flag/teleport) is computed server-side |
| filmed clip → unblurred delivery | a clip with faces must not pass the gate when blur_enabled (enforced via action='hold' read by mux-webhook) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Information Disclosure | GOOGLE_VISION_API_KEY | mitigate | Read from Deno.env only (same as signage-check); never returned to client; never logged |
| T-06-07 | Tampering | client-supplied fraud_signals | mitigate | fraud-eval recomputes the teleport verdict server-side from scout_locations + filmed coords; client bag is provenance, not the verdict (D-04) |
| T-06-08 | Information Disclosure | clips.fraud_signals (PII-ish location bag) | accept | Location accuracy/coords already stored (filmed_lat/lng Phase 5); service-role-only read; no new exposure |
| T-06-09 | Tampering | clip claiming blur_status='blurred' to skip gate | mitigate | blur_status is service-role-only (Plan 01 RLS); on-device path sets it ONLY via a server write (Plan 04 design) — client cannot self-assert blurred |
| T-06-10 | Denial of Service | Vision call per clip | mitigate | blur_enabled=false at launch = zero Vision calls; single-thumbnail (not per-frame); fail-open on error (Pitfall 5) |
| T-06-11 | Privacy / unblurred delivery | faces in delivered clip | mitigate | faces>0 + not-blurred -> action='hold'; mux-webhook (Plan 03) reads hold and holds in blur_review (D-07) |
</threat_model>
