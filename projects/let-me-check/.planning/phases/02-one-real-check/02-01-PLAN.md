<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (anon key + user JWT) → Postgres/RLS | Every read/write from the RN app crosses here; the anon key is public so RLS + SECURITY DEFINER authz is the only control |
| SECURITY DEFINER function internals → tables | Definer functions run as owner and bypass RLS on their own writes — they MUST self-authorize against auth.uid() |
| Realtime channel → subscriber | Postgres Changes re-checks every event against the subscriber's RLS before delivery |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering/Elevation | accept_check (double-accept race) | mitigate | Atomic `UPDATE ... WHERE status='dispatching' AND scout_id IS NULL`; losing accept matches 0 rows -> raises 'already taken'. Verified by accept_check_atomic.test.sql (Task 1). |
| T-02-02 | Tampering | transition_check (illegal jump e.g. requested->delivered, re-rate) | mitigate | `is_valid_check_transition` table rejects any edge not explicitly legal; no client UPDATE policy on checks. Verified by check_transitions.test.sql throws_ok. |
| T-02-03 | Elevation | transition_check (wrong actor drives filming/delivered/rate/cancel) | mitigate | Actor authz inside the definer fn: auth.uid() vs seeker_id/scout_id; raises on mismatch. Verified by wrong-actor throws in Task 1. |
| T-02-04 | Information Disclosure | Scout reads another seeker's check/delivered clip | mitigate | Narrow RLS (0009): open `dispatching && scout_id IS NULL` + own `scout_id = auth.uid()` only; clips_select_participant confines clip reads to the check's seeker/assigned-scout. Verified by scout_rls.test.sql count=0. |
| T-02-05 | Tampering | Deliver without a clip (empty/fake delivery) | mitigate | transition_check 'delivered' guard requires `exists (select 1 from clips where check_id=...)`. Verified by deliver-without-clip throws (Task 1). |
| T-02-06 | Information Disclosure | Seeker reads another seeker's check via Realtime | mitigate | Postgres Changes RLS-checks each event; checks_select_own confines to own rows; realtime auth token = session (verified on-device in Plan 02 checkpoint). |
| T-02-07 | Repudiation | Hide a bad transition by editing the log | accept | Phase-1 append-only immutability trigger on event_log already blocks UPDATE/DELETE; transition_check/accept_check write the log server-side. No new mitigation needed this phase. |
