<objective>
Author the three net-new Supabase Edge Functions that ARE the server side of the video pipeline: mint a signed Mux upload URL, finalize via a signature-verified idempotent webhook, and mint per-Seeker signed playback tokens. The webhook is the ONLY actor allowed to drive a check to `delivered`, so a dropped client network can never fake delivery. These are the FIRST Edge Functions in the project (`supabase/functions/` does not exist yet).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RN client -> Edge Function | Caller is authenticated but untrusted re: which check they own; functions must self-authorize. |
| Mux -> mux-webhook | External POST drives `delivered`; only a valid Mux signature may be trusted. |
| Edge Function -> Mux API | Secrets cross here; they live ONLY in Edge-Function env, never returned to a caller. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Spoofing | forged Mux webhook | mitigate | `verifyMuxSignature` rejects before any DB write; tested directly in _shared/mux.test.ts (forged-sig -> throws) AND in mux-webhook (bad-sig -> 401). HIGH. |
| T-03-05 | Information Disclosure | non-owner watches another Seeker's clip | mitigate | mux-playback-token mints ONLY for `seeker_id === caller.id`; asset is `playback_policy:['signed']` so the stream URL needs the JWT; non-owner -> 403. HIGH. |

HIGH. |
