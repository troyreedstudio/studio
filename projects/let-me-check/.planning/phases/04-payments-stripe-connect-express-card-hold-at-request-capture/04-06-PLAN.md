<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Stripe SDK | Card data goes straight to Stripe (PCI); the app never touches raw PAN |
| publishable key in client | Public by design; secret key never ships in the bundle |
| deep-link return → go-online | Untrusted; eligibility comes from the server status edge |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-26 | Information Disclosure | card PAN in app | mitigate | PaymentSheet (Stripe-hosted) collects card data; the mock card-entry form is removed (grep gate on formatCardNumber) — no raw PAN in our code |
| T-04-27 | Tampering | book without a successful hold | mitigate | createCheck runs only after presentPaymentSheet succeeds (order grep-asserted); decline blocks the booking (D-02) |
| T-04-28 | Elevation of Privilege | Scout goes online without KYC | mitigate | "go online" gated on server status edge eligible=true, not the deep-link return (Pitfall 5) |
| T-04-29 | Spoofing | client forging onboarding completion | mitigate | Eligibility is a live server read of the Stripe account; client cannot self-assert it |
| T-04-30 | Information Disclosure | publishable vs secret key | accept | Publishable key is public by design; secret key stays in Edge (Plan 05) — no client exposure |
</threat_model>
