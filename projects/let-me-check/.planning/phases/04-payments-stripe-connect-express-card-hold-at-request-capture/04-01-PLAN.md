<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe webhook → Edge Function | Untrusted POST claims a Stripe event; signature must be proven before trust |
| Deno.env → exported helpers | Secrets must stay inside the module; no helper returns one |
| client → payments/refund/connect tables | RLS must confine reads to the owning seeker/scout and bar client writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | stripe-webhook (future consumer of verifyStripeSignature) | mitigate | `verifyStripeSignature` HMAC-SHA256 over `${t}.${rawBody}`, v1-only, 300s replay window — proven by Deno tests A1–A4 |
| T-04-02 | Information Disclosure | _shared/stripe.ts | mitigate | Secrets read via requireEnv only; B1 test proves no helper return contains STRIPE_SECRET_KEY; grep gate blocks `return` of secrets |
| T-04-03 | Tampering | payments table | mitigate | No client INSERT/UPDATE/DELETE policy; service role writes only (mirrors checks.status RLS); pgTAP asserts row_security_active |
| T-04-04 | Elevation of Privilege | refund_requests | mitigate | INSERT policy requires auth.uid() = seeker_id on own check; no client UPDATE (review server-owned) |
| T-04-05 | Repudiation | all payment mutations | mitigate | event_log (0001, immutable) is the audit trail; edges log every payment event via log_event |
</threat_model>
