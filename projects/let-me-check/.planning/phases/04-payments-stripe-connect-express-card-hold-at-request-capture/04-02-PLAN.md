<objective>
Build the auth-and-hold front gate (D-01/D-02). The `stripe-create-payment-intent` Edge Function creates a manual-capture PaymentIntent on the platform account, ensures a Stripe Customer exists for the user, mints an ephemeral key for saved-card support, and returns ONLY the non-secret values the PaymentSheet needs. A shared `pricing.ts` becomes the single source of tier amounts (minor units + currency). The client `payments.ts` lib defines the typed contract the payment screen (Plan 06) will call before `createCheck`.

Purpose: This is the Uber gate — a hold must succeed before a check can be created. The amount is server-authoritative (never trust a client price). Interface-first: define `pricing.ts` and `payments.ts` here so the capture edge (Plan 03) and the UI wiring (Plan 06) consume fixed contracts.
Output: the create-PI edge + its Deno test, the shared pricing table, and the client payments lib.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → stripe-create-payment-intent | Client supplies only `tier`; amount is server-derived (never trust a client price) |
| Edge → Stripe API | Secret key used server-side only; response strips it |
| ephemeral key → client | Short-lived, session-scoped; never persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | amount/price | mitigate | Amount read from `_shared/pricing.ts` server-side; client cannot influence the charged amount (grep gate: no hard-coded amount at create) |
| T-04-07 | Spoofing | caller identity | mitigate | callerId resolved from the bearer via authedClient.auth.getUser(); null -> 401 (test 1) |
| T-04-08 | Information Disclosure | PI response | mitigate | Returns only client_secret/customerId/ephemeralKey/paymentIntentId; no-leak Deno test asserts the secret key never appears |
| T-04-09 | Information Disclosure | ephemeral key | mitigate | Generated per request, never stored; scoped to the one customer |
| T-04-10 | Repudiation | hold creation | mitigate | log_event 'payment.authorized' written for every PI |
</threat_model>
