<objective>
Build ultra-low-friction Scout payout onboarding via Stripe Connect Express (SCOUT-01/SCOUT-02, PAY-03). `stripe-connect-onboard` records the Scout Code consent, creates (or reuses) the Scout's Express account, and returns a fresh single-use hosted onboarding URL. `stripe-connect-status` is the authoritative go-online gate — it fetches the live account and returns whether charges_enabled && payouts_enabled, so the app never lets a Scout go online on an incomplete account.

Purpose: Stripe absorbs all KYC/tax/identity (no background check, no separate ID step per PROJECT.md). The only identity is Stripe's own onboarding. The status edge prevents the classic pitfall of trusting the deep-link return when Stripe hasn't finished verification.
Output: stripe-connect-onboard + stripe-connect-status edges, each with a Deno test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → connect-onboard/status | Scout-scoped; the caller may only touch their own connected account |
| account_link URL → client | Single-use, short-lived; never stored or reused |
| deep-link return → go-online | The return URL is untrusted for eligibility; live account read is authoritative |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-17 | Spoofing | onboard/status caller | mitigate | scoutId resolved from bearer; null -> 401 (test 1); a Scout can only onboard/query their own account |
| T-04-18 | Information Disclosure | account_link reuse/interception | mitigate | Fresh single-use link per request, never stored in DB (Pitfall 4); returned only to the authed owner |
| T-04-19 | Elevation of Privilege | go-online with incomplete KYC | mitigate | Eligibility = live charges_enabled && payouts_enabled (Pitfall 5), not the deep-link return |
| T-04-20 | Tampering | client forging onboarding state | mitigate | scout_stripe_accounts has no client write policy (0011); only service role + the account.updated webhook update it |
| T-04-21 | Repudiation | onboarding consent | mitigate | accepted_scout_code_at stamped server-side; 'scout.connect_onboarding_started' logged |
</threat_model>
