<objective>
Build the server side of in-app account deletion (Apple 5.1.1(v) hard requirement, D-03). This is the BLOCKING wave: the migration and Edge Function must exist before the client entry points (Plan 03) and the live deploy (Plan 04) can land.

Purpose: Apple rejects any account-creating app that does not let users delete their account from inside the app. This plan delivers the cascade-safe deletion engine.

Output: migration 0021 (audit table + `delete_my_account` RPC), the `delete-account` Edge Function, and RED tests (pgTAP + deno).

CRITICAL SCHEMA FACT (verified by reading the migrations — do NOT trust the research's cascade assumption):
The ONLY tables with `on delete cascade` on `auth.users(id)` are: `profiles`, `consents`, `device_push_tokens`.
ALL of these have NO cascade and WILL block `auth.admin.deleteUser` with a foreign-key violation unless handled first:
  - checks.seeker_id, checks.scout_id  (references auth.users(id), no cascade)
  - saved_places.user_id, recents.user_id, recurring_checks.user_id, payment_methods.user_id
  - ratings.seeker_id
  - payments.check_id -> checks(id)  (no cascade; child of checks)
  - refund_requests.seeker_id + refund_requests.check_id
  - scout_stripe_accounts.scout_id
  - scout_locations.scout_id
  - clips.check_id -> checks(id)  (child of checks)
  - event_log.actor_id  (nullable FK, no cascade — must be NULLed)
Therefore `delete_my_account` MUST resolve every one of these before `deleteUser` is called.

| T-11-01 | Tampering (IDOR) | delete-account uid resolution | mitigate | uid derived ONLY from authedClient.auth.getUser(); req-body user_id ignored; deno test asserts a hostile user_id body is not honored |
